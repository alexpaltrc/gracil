# 0020 — The tray icon is drawn by Gracil, on a thread of its own

**Status:** Accepted, built (2026-10-03). Carries out [0007](0007-close-to-tray.md) and the tray
part of [0015](0015-piedra-identity.md) and [0016](0016-app-icon.md).

**Context.** Spec §54 and §54.1 ask for a tray icon that is present while Gracil runs, shows
Idle, Processing, Paused and Error, and offers Exit, which asks first when work would stop. Iced
0.14 has no tray support, and its event loop must not be blocked by a popup menu. The delivered
artwork has light and dark tray icons but no pictures for the other states.

**Decision.**

1. `gracil_windows::Tray` runs on its own thread with a hidden top-level window (class
   `Gracil.Tray`, never shown). It is not a message-only window, so it receives the broadcasts it
   needs: `TaskbarCreated` (Explorer restarted; the icon is added again) and `WM_SETTINGCHANGE`
   with `ImmersiveColorSet` (the taskbar's theme changed; the icon is redrawn).
2. The icon uses `NOTIFYICON_VERSION_4`. A click or Enter on it opens the main window (since
   [0021](0021-mini-window.md), the mini-window); the right-click menu holds **Open Gracil**
   (default) and **Exit**. The menu runs on the tray's thread, so the window keeps drawing while it
   is open. Events reach the app through the same channel as pipe requests.
3. Gracil draws every state itself at the size Windows asks for (`SM_CXSMICON` at the system's
   DPI), from the same shapes as the delivered tray artwork, with the support in the taskbar's
   contrasting stone tone:
   - Idle: the marble whole;
   - Processing: the marble's rim, filling clockwise from the top as the video advances;
   - Paused: two bars in place of the marble;
   - Error: the marble in the warning amber.
   Drawing all states the same way keeps them aligned to the pixel; mixing the delivered ICOs with
   drawn states would make the icon shift as it changes. The picture is redrawn only when the
   progress moves by a 40th, the tooltip when it moves by a whole percent.
4. Error means a problem the user hasn't seen yet: something failed while the window was closed.
   Opening the window clears it. "Not smaller" is an expected result, not an error.
5. Closing the window hides it; work carries on. **Exit** quits at once when nothing is
   compressing or waiting. Otherwise it opens the window on a question that says exactly what
   stops (§54.1), with **Exit** and **Keep working**. The question goes away by itself if the work
   finishes first.
6. If the tray icon can't be created, closing the window acts as Exit, so Gracil never runs with
   no way back to it.

**Consequences.**

- The classic popup menu follows Windows' light look even in dark mode; owner-drawing it was not
  worth the code.
- Changing the tray artwork means changing the shapes in `tray/picture.rs`, not only the ICO
  files.
- Results nobody chose for are still deleted on Exit, as before (ADR 0009).
